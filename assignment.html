Advanced Corporate Finance · EBM232A05 · The assignment, 2026–27

The replication project

One piece of work, assessed at four moments: teams of five reproduce the headline result of a published empirical corporate-finance paper from raw WRDS data — with AI use required, documented, audited, and graded.

Weights for 2026–27: 80% supervised exam / 20% project (changed from 60/40). The change has programme-director approval (August 2026); the course-dossier re-registration is in progress. A side effect of 20%: the project no longer exceeds the 25% threshold, so the dossier’s group-repair clause lapses — the exam resit is unaffected.

What teams actually do

Each team receives a published empirical corporate-finance paper from a curated menu, plus a team-specific parameter sheet (sample window, filters, target cells) so that no two teams solve the identical problem. Starting from raw WRDS data, they rebuild the sample, reproduce the paper’s headline table within a stated tolerance band, reconcile what does not match, and then run one critical extension the paper did not do — motivated by a friction from the course. AI coding tools are not merely allowed but required: the assessed object includes the documented AI process itself — where the AI was wrong, how it was caught, and the commit that fixed it.

Why the redesign

The 2025 course graded essays and prohibited AI — a policy that had become unenforceable and, worse, misaligned with what graduates will actually do. This design inverts it. But the inversion is made honest by a second fact: current agentic AI tools can produce the deliverables end to end — code, write-up, even plausible commit histories and AI logs. Polished products therefore no longer certify individual mastery, and nothing that leaves the classroom is graded as if they did. What certifies mastery is what happens in the room: the supervised digital exam (80%) and the live code defence. The project keeps its weight as the programme’s hands-on AI-and-data component — where the skills are built — while the certification sits where it can still discriminate.

The four assessment moments

Deadlines are 22:00 the day before the tutorial; the moment is the tutorial at which work is assessed and returned, so every team gets corrective feedback before the result is locked in.

MomentWeekAssessedPoints (of 100)
M139Scoping memo — target table, claims list, variable definitions, data plan, repo skeleton. Also the proceed / no-proceed gate. 10
M241Reproduction checkpoint — target cells against the paper’s printed values (20), plus the sample-construction funnel and reconciliation memo (5). 25
M342Final package — reproducible repository (20), AI-process dossier (15), theory-linked critical extension (20). 55
M443Individual reflection (graded per student), plus the in-tutorial code defence — which caps, and does not add to, the team’s process marks. 10

M1–M3 carry one grade for all named members; M4’s reflection is individual. The mock exam posts in week 39.

What keeps it honest

  • Team-specific parameters — sample windows and target cells differ per team, so a submission cannot be borrowed, bought, or bulk-generated once and shared.
  • Tolerance bands against printed values — the reproduction is graded against the paper’s own numbers, which an AI cannot fake its way past: the data either reconciles or it does not.
  • The live code defence — a team that cannot navigate and explain its own repository has its process marks capped. This, not the transcript log, is the authenticity instrument.
  • The 80% supervised exam — the certifying instrument for individual mastery, including one evidence-interpretation item drawn from the project’s methods thread.

Onboarding — no Python or Git assumed

The project assumes introductory econometrics, and nothing else. The tooling is built up inside the course: the week-36 tutorial is the project kickoff (teams, menu, skeleton repository, a step-by-step walkthrough), a first-time setup guide covers Git, Python and the AI assistant one screen at a time, and the week-37 tutorial is WRDS onboarding. The methods thread continues in the tutorials — panel and regression mechanics in week 38, event-study mechanics in week 41 — timed so each skill arrives just before the project needs it.
